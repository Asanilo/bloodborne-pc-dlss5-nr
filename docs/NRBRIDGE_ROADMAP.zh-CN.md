# NRBridge 路线图

> 更新：2026-10-26 · 依据 `nrbridge` @ `c937e07` 与最近一次实机验收。
> **本文是方向与前置条件，不表示已经完成。** 已完成能力见 [项目现状](PROJECT_STATUS.zh-CN.md)。
> 优先级：**P0** 阻塞日常游玩 / **P1** 影响画质与稳定 / **P2** 方向性研究 / **P3** 分发与工程债。

## 0. 当前能力边界（作为起点）

已具备：NR → 持久视觉历史 → 原生 SR → Present 的完整链路；FG 独立开关（FSR x2 / DLSS 2X–6X）；NR-only；动态尺寸；Old/New 内存；原生鼠标；完整启动器。

尚未具备：NR 时域画质的普适结论、Smooth Motion、原生 Vulkan 下的 NR、NR-only+FG 之外的无人值守长稳、公开发布。

## A. NR 时域画质（P1）

**目标**：消除 NR 的着色闪烁、有效历史骤降与亮尾，使历史覆盖变化时不再出现可见脉动；让分数运动与深度边缘的时域结果与参考实现一致。

**已有基础（已合入）**：持久历史双 slot、真实源编号、历史写回与 TTL、候选准入（admission）、`displayHistory` 过渡权重、可选策略 `BB_NR_VISUAL_TRANSITION=fade-new`。

**剩余工作**

1. 把 `fade-new` 从"实验策略"推向默认：需要更多场景（NR-only、1440p、Old、NR+FG）的实际试玩判断，现有数据只覆盖 NR→SR / 1080p Quality / New。
2. 分数运动（fractional motion）与深度边缘的 NVIDIA 等价性未达成；最近邻深度与 8bit 双线性分数模拟都不能单独修好全部用例。
3. 单步历史采样/发布误差仍需定位，方向是更高分辨率的同版本时域参考。
4. 用直接写入的持久 ping-pong 历史图替换研究期的 pack/copy 路径。

**必要前置**

- 可重复的短动作采集窗口（`quality_scenario.py` / `quality_window.py` 已有，需 `BB_MEMORY_PROFILE=1` 私有环境）。
- 一套可信的视觉判定方式。**已被否定**：X11 录制 A/B 短片被玩家指出卡顿，已停止作为验收依据；加长过渡到 6 帧/100ms 的方案使候选采纳间隔翻倍、波动反而升高，已移除运行选项（源码留在 `experiment/nr-temporal-ab-20261025`，不合流）。
- 每次策略变更需完整走正常退出与资源退休判定，不能用功能回归替代视觉验收。

**风险**：任何"把新画面压暗/混色"的近似都会引入亮暗边，玩家主观判定优先于内部指标。

## B. Smooth Motion（P2）

**目标**：在 FG 之外提供运动平滑选项，且与 NR、SR、FG 的后端切换互不破坏。

**现状**：启动器与游戏内均为**不可选**。历史 M3 阶段的下线原因是"正常退出未通过验收"，不是性能问题；代码路径与设置项保留，未删除能力。

**必要前置（硬阻塞）**

1. 正常退出的资源退休链完整：GPU/FD 末用、生成帧编号、Presenter 消费 ACK 全部闭环。
2. 与现有 FG 算法的运行时互斥规则明确（切换需重启的提示已具备，需覆盖 Smooth Motion）。
3. 一套不依赖录像的判定方式（同上 A 节）。

**优先级说明**：不阻塞当前游玩，因此在 NR 时域画质与 FG 画质之后。

## C. Native Vulkan NR（P2，研究线）

**目标**：让 NR 推理脱离 Wine/NGX 中间层，在原生 Linux Vulkan 上直接消费颜色、深度、运动向量与持久历史，形成可被其他原生游戏复用的接入方式。

**现状**：研究在独立仓库 `/home/arinp/Code/dlss_vulkan`（分支 `wip/native-nr-temporal-20261025`）进行，不是本仓库的运行路径。研究结论明确**未完成**：完整 NVIDIA 时域等价性、生产级 NRBridge IPC 时序、游戏内集成都还没有。

**必要前置**

1. 首帧与连续帧的 RGB 逐字节等价（目前只有受控探针与部分帧一致）。
2. 历史采样/发布的单步误差定位（与 A 节第 3 项同源）。
3. 生产级跨进程时序（当前 NRBridge 走 Wine Helper + 共享 dmabuf），需要可验证的 IPC 预算与背压。
4. 模型只能在用户自有且已授权的环境中使用，不能进仓库。

**风险**：这是一条独立的研究线，不能用"研究跑通"描述成"功能可用"。

## D. FG 画质与性能（P1）

**目标**：让生成帧在快速转镜、植被与 HUDless 场景下与真实帧保持几何一致，并让高倍率 MFG 的代价可预期。

**剩余工作**

1. **FSR FG 植被位置错误**：快速转镜时生成帧植被错位，未解决；关闭 NR 不能消除。
2. **NR-only + FG 的手感与长稳**：功能已打通并有短窗数据，缺长时游玩与主观操作手感确认。
3. **高倍率显存与帧率**：3X/6X 会增加生成工作与显存，需给出按分辨率的可用建议区间，而不是宣称吞吐提升。
4. **等待与 pacing**：producer 真实完成等待、Helper Evaluate 队列、Native 响应等待三者重叠，尚未针对 producer 依赖做优化。
5. 1440p 目前是内部 SR/FG 输出，物理 1440p 扫描、16:10、超宽、4K、HDR 均未验收。

**必要前置**：稳定的画面判定（同 A 节）、真实显示设备覆盖、以及保留现有"不把 Present 数当帧率"的证据口径。

## E. 稳定性与兼容性（P1）

- 长时间游玩与异常退出恢复：现有保护（HOLD、资源保护、存档独立副本）保留，需覆盖更长的会话与更多异常路径。
- 平台依赖：当前部分依赖要求 GLIBC 2.44，面向 CachyOS；跨发行版是明确的未完成项。
- 真实联机、DLC、手柄/触点/体感混合输入仍属未验收范围，按需推进，不阻塞单机。

## G. 分发（P3）

**目标**：在不破坏许可证与上游归属的前提下提供可复现的构建与发布。

**必要前置**：跨发行版依赖收敛（GLIBC、字体、Python/GI、在线库与 CJK 资源打包）、CI 可复现构建、发布前的新身份与验收记录。当前明确**不公开发布二进制**。

## 优先级汇总

| 顺序 | 方向 | 为什么现在 |
|---|---|---|
| 1 | D. FG 画质（植被伪影、长稳） | 直接影响日常游玩观感 |
| 2 | A. NR 时域画质 | 已知闪烁/亮尾是玩家最常反馈的问题 |
| 3 | E. 稳定性 | 保护现有可用状态，避免回归 |
| 4 | F. 工程债与退役 | 成本低、避免后续误引用 |
| 5 | B. Smooth Motion | 有硬阻塞，排在画质之后 |
| 6 | C. Native Vulkan NR | 研究方向，周期最长 |
| 7 | G. 分发 | 依赖前面全部收敛 |

依赖关系：A 的"单步历史误差"与 C 的第 2 项同源；B 依赖 E 的退出链；G 依赖 E 与 D 的覆盖度。
