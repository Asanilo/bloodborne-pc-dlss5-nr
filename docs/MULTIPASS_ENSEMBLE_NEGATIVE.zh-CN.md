# 已终止的 A/B 融合实验

2026-10-30 归档。该实验不是 OptiScaler 的串联 MultiPass，不进入新的串联候选。

旧实验提交为 `5b8165e`（实现）、`b50e74c`（实机结果）、`8302356`（低 B CPU 阶段），
原分支名 `research/multipass-nr`。用户授权保留本页后清理旧分支、工作树和专属产物；
本页保存结论与边界，不承诺清理后仍可复现原始证据。

## 做过什么

同一原图 Encode 后交给两个独立 Feature，各自 Evaluate、Resolve，再按 75%/25%
融合 HDR 结果。A：Style 0、Intensity 1；B：Style 1、Intensity 1。两路同为 1280×720，
再经过现有 Native temporal/SR 至 1920×1080。每个作业均 Reset=1。
后续低 B 版本将 B 降为 640×360，仅完成 CPU/编译检查，没有 GPU 画质或性能验收。

## 2026-10-29 短场景观测

RTX 4060 Laptop 8 GB，驱动 615.78.08，诊所机位；FG/SM 关闭，90fps 上限。
同一 seed 分别进行约 6 秒静止、4.7 秒转镜。单遍/融合各一轮，未交换顺序重复。

时间戳为同队列命令及依赖的 scoped 区间，不是纯推理时间；显存是整设备采样，
343 MiB 差额不能全部归属第二 Feature。最终显示截图未呈现足以支持额外成本的明确
细节或材质优势，不能据此宣称改善稳定性。历史统计的采样与更新周期存在相位混叠，
不支持定量稳定性排名。未完成真实模型 A/A、纯 B 或室外控制。

## 结论

停止此方向。该参数组合增加成本且未证明画质收益；这不是串联 MultiPass 的负面结果。
新的候选从干净 nrbridge 基线实现 Encode → NR1 → NR2 → 单次 Resolve，
不沿用融合代码、低 B、缓存或新残差算法，也不以本表评价串联性能。
